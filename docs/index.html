SSJ EVENTS · USER GUIDE

取扱説明書User Guide

SSJ Events Listで予定を管理し、選んだ予定をGoogleカレンダーへ反映するためのガイドです。日時の入力・反映期間の基準は日本時間（JST）です。

Manage events in SSJ Events List and publish selected events to Google Calendar. Event times and publishing date ranges are entered in Japan Standard Time (JST).

ブラウザーの優先言語から日本語・英語を自動選択します。上部のメニューで任意に変更し、「自動」で自動選択に戻せます。

The guide selects Japanese or English from your browser preferences. Choose a language above, or select Auto to follow the browser again. Japanese on-screen button names are included in the English instructions.

02ログインと認証保持Sign-in and session retention

本人確認後は、ログイン保持のON/OFFにかかわらず、ヘッダーにアクセス者本人のメールアドレスを常時表示します。「Googleログイン設定」とログイン前の初回設定ボタンは、元シート所有者だけに表示します。設定の取得・保存・診断もサーバー側で所有者に限定します。

After identity verification, the accessing user's email remains visible in the header whether session retention is ON or OFF. Google sign-in settings and the setup button before sign-in are shown only to the source spreadsheet owner. The server also restricts reading, saving and diagnosing these settings to the owner.

「Googleでログイン」で本人確認を行います。管理機能は、元シート所有者と、所有者が指定したGoogleグループの活動中のメンバーが利用できます。スタッフには、元シートへの指定グループの有効な編集共有も必要です。

  • このブラウザーで本人確認を7日間保持するは初回ON。同じブラウザープロファイル・同じアプリで最大7日間保持します。
  • OFFでは現在のタブ内だけ、最大6時間です。利用するたびに期限が延びる方式ではありません。
  • 保存をブラウザーが拒否した場合は、実際の保持範囲を画面に表示します。
  • Google確認用タブは自動終了を試みます。閉じない場合は、そのタブを手動で閉じて元の管理画面へ戻ります。開かない場合は画面内の明示リンクを使います。
  • 「ログアウト」で認証情報と画面の管理データを消去します。実行中の処理がある間はログアウトできません。

期限切れでは未保存入力・対象選択・期間・画面内AI設定を残して再確認します。同じGoogleアカウントを選んでください。別アカウントでは編集中の操作を引き継ぎません。失敗した保存・削除・反映・AI生成は自動再実行しません。

Use Sign in with Google (Googleでログイン) to verify your identity. Management is available to the source spreadsheet owner and active members of the designated Google group. For staff, the source spreadsheet must also have an active editor share for that group.

  • Remember verification in this browser for 7 days (このブラウザーで本人確認を7日間保持する) is initially ON. Verification lasts up to 7 days in the same browser profile and app.
  • With it OFF, verification stays only in the current tab, for up to 6 hours. Using the app does not extend the deadline.
  • If browser storage is blocked, the screen explains the actual retention available.
  • The Google verification tab attempts to close automatically. If it stays open, close that tab and return to the original management tab. If a pop-up is blocked, use the explicit sign-in link.
  • Log out (ログアウト) clears verification and private data from the screen. Logout is disabled while a business operation is running.

When verification expires, the app keeps unsaved input, selections, dates and AI settings while you verify again. Choose the same Google account. A different account cannot silently take over an unfinished operation. Failed saves, deletions, publishing and AI generation are never replayed automatically.

03予定の閲覧・追加・編集・削除View, add, edit and delete events

内容を確認する

「SSJ Events List」の予定名をクリックすると、A～S列の内容を全画面で表示します。「前の予定」「次の予定」でページ送りし、「閉じる」またはEscで戻ります。閲覧だけではデータを変更しません。

追加・編集する

上部の「予定を追加」、または各行の「編集」を押します。新規予定は「繰り返しなし」、保存時のAI設定はすべてOFFから始まります。必要な項目を入力し「保存」します。日付や繰り返しの選択に合わせて、関連する入力欄だけが表示されます。

削除する

各行の「削除」で対象名を確認して実行します。その行の予定内容を空にし、行番号を詰めずに削除記録を残します。カレンダー側を消すには「削除を反映する予定」で対象を選び、期間を指定して「カレンダーへ反映」を実行します。期間外の開催分は残ります。

保存時に「内容が変更された」と表示された場合は、別の操作と競合しています。入力内容を確認してから一覧を再取得し、最新の予定を開き直してください。

Inspect an event

Click an event title in SSJ Events List to view columns A–S full-screen. Use Previous event (前の予定) and Next event (次の予定), then Close (閉じる) or Esc to return. Viewing does not change any data.

Add or edit

Choose Add event (予定を追加) at the top or Edit (編集) on a row. New events start with No recurrence (繰り返しなし); all AI options for saving start OFF. Enter the required fields and Save (保存). The editor shows the fields relevant to your date and recurrence choices.

Delete

Choose Delete (削除) on a row and confirm the event name. The app clears the event cells and keeps a deletion record without shifting row numbers. To remove its Calendar occurrences, select it under Deleted events to apply (削除を反映する予定), choose the date range and publish. Occurrences outside the range remain.

A message that the event has changed indicates a conflict with another edit. Check your unsaved work, refresh the list and reopen the latest event before trying again.

04開催日・終日・繰り返し・色Dates, all-day events, recurrence and colors

単発・期間イベント

「開催日の指定」で「日にち・期間をカレンダーから指定」を選び、開始日を入力します。終了日が空欄なら開始日と同じです。終日なら時刻は不要です。終日の終了日はその日を含みます。複数日の期間は連続する1件の予定です。

時刻指定で日をまたぐ場合は、翌日以降の終了日も選びます。入力の基準はJSTです。参加者向けの時刻確認にはローカルタイム案内ページを利用できます。

繰り返し

「繰り返しあり」で日・週・月・年と間隔を指定できます。間隔2は2日・2週・2か月・2年ごとです。1回分が複数日でも繰り返せます。例えば11月15～17日の3日間を毎月繰り返すと、12月も15～17日の期間になります。

  • 週・曜日の形式では「毎週」または「第1週～第5週」と曜日を指定します。予定名の「1st」「2nd」等から推測しません。
  • 日付指定の月・年単位は基準日の同じ日付です。31日や2月29日など、該当日がない月・年の回は作りません。
  • 「終了日」は1回分の期間。「繰り返し終了日」は新しい開催回を始める最終日です。空欄なら無期限です。
  • 反映期間にも終了日を指定した場合は、繰り返し終了日との早い方まで反映します。最終回の1回分の長さは切り詰めません。

予定色

「カレンダー色（S列）」で選びます。空欄は淡い青です。保存後、対象と期間を選んで反映すると色も更新します。Googleカレンダー上で直接変更した色も、次の反映ではS列の指定に戻ります。Google Sitesの標準埋め込みでは、同じ色が異なって見える場合があります。

One-time and multi-day events

Choose Specify dates / a date range (日にち・期間をカレンダーから指定) and enter the start date. A blank end date means the same date as the start. All-day events need no time fields. Their end date is inclusive. A multi-day range creates one continuous event.

For timed events crossing midnight, choose the following day or a later end date. Input uses JST. Attendees can use the local-time information page.

Recurrence

Enable Recurrence (繰り返しあり) and choose days, weeks, months or years with an interval. An interval of 2 means every 2 days, weeks, months or years. A multi-day occurrence can also repeat: a monthly event from November 15–17 repeats on December 15–17.

  • The week-and-weekday format supports Every week (毎週) or the first through fifth occurrence of a weekday in each month (第1週～第5週). Words such as “1st” or “2nd” in the title do not determine the schedule.
  • Date-based monthly or yearly recurrence uses the anchor date. Months or years without that date, such as the 31st or February 29, are skipped.
  • The event end date controls one occurrence. The recurrence end date (繰り返し終了日) is the last date on which a new occurrence can start. Blank means no end.
  • If the publishing range also has an end date, the earlier limit applies. The duration of the final occurrence is not shortened.

Event colors

Use Calendar color / column S (カレンダー色). Blank defaults to pale blue. Save, then publish the event for the selected range to update the color. A color changed directly in Google Calendar is reset to the column-S choice on the next publish. Google Sites’ standard calendar embed may display colors differently.

05グループ通知の件名・詳細Group notice title and details

K列がASCIIのグループ通知タイトル、L列が通知詳細です。L列の先頭にはK列の件名を省略せず全文入れます。元のイベント名、DJ・DM、講師・ガイド、時刻、会場などを続けます。講師・ガイドは演者と分けて表示します。

  • DJは「💿️🎵DJ」、DMは「💃🕺DM」、講師・ガイドは「⏹️Instructor or Guide」。各区画の末尾に「＊敬称略」を付けます。
  • 時刻は「🕒Time 22:00-24:00 JST」の形式です。会場には「🔻」を付けます。
  • ブラウザーで会場リンクが開かない場合の案内は、独立した「--」の行を挟んで本文末尾へ置きます。
  • 手で編集したK・L列は欄ごとに保持します。自動作成に戻したい欄は空欄にして保存します。

件名K＋本文Lの合計は510 UTF-8バイト以内です。 510文字ではありません。日本語・絵文字・改行も数えます。超過時は保存前に停止し、件名を途中で切ったり「...」へ省略したりしません。

「通知文だけ再作成」は選択した行のK・L列を更新します。カレンダーの説明へ反映するには、その後に「カレンダーへ反映」を実行します。

Column K is the ASCII notice title; column L is the notice body. The body starts with the complete, unabridged title from K, followed by the original event name, DJ/DM, instructor or guide, time and venue. Instructors and guides have a separate section.

  • Labels are “💿️🎵DJ”, “💃🕺DM” and “⏹️Instructor or Guide”. Each populated people section ends with “＊敬称略” (honorifics omitted).
  • The time format is “🕒Time 22:00-24:00 JST”. The venue uses “🔻”.
  • The fallback instruction for a browser venue link appears at the very end of the body, after its own “--” separator line.
  • Manual edits to K and L are preserved separately. Clear a field and save to return it to automatic generation.

The combined title K + body L must fit within 510 UTF-8 bytes. This is not 510 characters. Japanese, emoji and line breaks count. An oversized notice is stopped before saving; titles are never silently cut or shortened to “...”.

Rebuild notices only (通知文だけ再作成) updates K and L for the selected rows. Publish afterwards to update their descriptions in Google Calendar.

06AIで説明を作成するGenerate descriptions with AI

AI設定は初期値がすべてOFFです。ONにして保存または通知文作成を実行したときに、対象の予定情報をGeminiへ送ります。説明書の閲覧や予定の確認だけではAIを実行しません。

設定動作
AI作成詳細が空欄のときに説明を作ります。入力済みの詳細は保持します。
AI上書きAI作成もONにしたうえで、入力済みの詳細を作り直します。
AI全文作成・上書きもONにし、定型区画を追加せず詳細全文を作ります。先頭の完全なASCII件名と510バイト制限は維持します。

1件だけ保存するとき

編集画面の詳細欄の下にある「保存時にAIで詳細を作成する」等を選びます。予定を開くたびにOFFへ戻ります。

一覧からまとめて作るとき

対象行を選択し、各行の「AI作成」「AI上書き」「AI全文」を設定して「通知文だけ再作成」を実行します。列見出しの「全件」で一括ON/OFFできます。対象の全選択とは別の設定です。

一括AIでは対象を1つのJSONにまとめ、1リクエストで送信します。選択や行の設定によって、通常作成・入力済み保持の行も混在できます。AIの結果が不正・通知上限超過・作成中の競合の場合は保存を停止し、自動再試行しません。AIで保存した詳細は、後からAIをOFFにしても保持します。

All AI options start OFF. When you explicitly enable them and save or rebuild notices, relevant event information is sent to Gemini. Reading this guide or inspecting an event does not run AI.

OptionBehavior
Create with AI (AI作成)Generate a description when the details are blank. Keep existing details.
Overwrite with AI (AI上書き)With AI creation also ON, regenerate existing details.
Full AI text (AI全文)With creation and overwrite ON, generate the whole description without appending the usual fixed sections. The complete leading ASCII title and 510-byte limit still apply.

Saving one event

Use the AI options below the details field in the editor. They reset to OFF each time you open an event.

Generating from the list

Select target rows, set their AI creation, overwrite and full-text checkboxes, then run Rebuild notices only (通知文だけ再作成). The All (全件) checkbox in each AI column toggles that option in bulk. These settings are separate from target selection.

Batch generation sends one JSON request for the AI targets, rather than one request per row. A selection may mix AI generation, ordinary generation and preservation of existing text. Invalid output, oversized notices or concurrent edits stop saving; there is no automatic retry. AI-generated details remain saved when AI is later turned OFF.

07対象と期間を選んで反映するSelect targets and a publishing range

操作ボタンは「反映内容を確認 → 通知文だけ再作成 → カレンダーへ反映」の順に並びます。強調表示される既定の操作は「反映内容を確認」です。反映期間のフォームをEnterキーで送信した場合も確認だけを行います。「通知文だけ再作成」は選択した予定のK・L列を更新し、公開するには「カレンダーへ反映」を押します。

The buttons appear in this order: Preview (反映内容を確認) → Rebuild notices only (通知文だけ再作成) → Publish to Calendar (カレンダーへ反映). Preview is highlighted as the default action. Submitting the publishing-range form with Enter also previews the changes. Rebuild notices only updates K and L for the selected events; click Publish to Calendar to publish them.

  1. 一覧の「対象」をチェックします。初回は全件選択です。「すべて選択」「すべて解除」も利用できます。
  2. 削除を適用する場合は「削除を反映する予定」も選びます。通知文作成では削除記録を対象にしません。
  3. 「開始日（日本時間・必須）」をカレンダーから選びます。
  4. 期限を決めるときだけ「終了日を指定する」をONにし、終了日を選びます。初期OFF、空欄は無期限です。
  5. 「反映内容を確認」で予定名・日時・繰り返し・件数・注意事項を確認します。
  6. 「カレンダーへ反映」を実行し、完了結果を確認します。

指定した期間内を置き換え、期間外は残します。選択外の行と、カレンダーに手入力した別の予定は変更しません。同じ内容なら再登録せず、変更があった予定は対象期間の旧開催分を削除して再登録します。

期間の境界はJSTで、その日に始まる開催分を基準にします。終わりの日を含み、日付をまたぐ1回分の長さは切り詰めません。反映開始日前に始まる単発・期間イベントは対象外です。週ごとに内容が違う予定は、それぞれのシート行に従います。

結果は上部の「イベントカレンダーを開く」で別タブから確認できます。この取扱説明書も「取扱説明書を開く」から別タブで開けます。

  1. Select Target (対象) checkboxes. All events are selected initially; Select all (すべて選択) and Clear all (すべて解除) are available.
  2. Also select any deletion records under Deleted events to apply (削除を反映する予定). Deletion records are not notice-generation targets.
  3. Choose the required publishing start date in JST (開始日).
  4. Enable Specify an end date (終了日を指定する) only when needed. It is initially OFF; blank means no end.
  5. Use Preview (反映内容を確認) to check titles, times, recurrence, counts and notices.
  6. Run Publish to Calendar (カレンダーへ反映) and read the completion result.

Publishing replaces occurrences within the specified range and keeps those outside it. Unselected rows and unrelated events entered manually in Calendar are left alone. Unchanged events are not recreated. Changed events have their old in-range occurrences deleted and recreated.

Range boundaries use JST and are based on the date each occurrence starts. The end date is included, and an occurrence crossing midnight keeps its full duration. A one-time or multi-day event starting before the range is excluded. Events whose details vary by week follow their separate spreadsheet rows.

Open Event Calendar (イベントカレンダーを開く) at the top to check the public page in another tab. Open User Guide (取扱説明書を開く) opens this guide in another tab.

08処理経過と結果を確認するRead progress and results

経過と結果は別ポップアップに表示します。開けない場合はアプリ内の別ダイアログに表示します。実行中は「閉じる」を隠し、完了時に「処理が終了しました（成功）。」または「処理が終了しました（エラー）。」と結果を表示してから「閉じる」を出します。

  • 上部の「経過を表示」から、その画面で開始した処理の結果を再表示できます。
  • 管理画面や経過ウィンドウを閉じても、サーバーで始まった処理は取り消されません。
  • エラー時は、対象行・原因・処理済み件数を読んでから再操作します。途中まで変更されている場合があります。
  • 削除後の再登録だけが失敗した場合、その予定が一時的に存在しないことがあります。結果を確認して同じ対象・期間を反映し直すと、未登録分を作成できます。
  • 認証の期限切れや通信切断のあと、保存や反映を連打せず、再確認後に「経過を表示」で処理結果を確認します。

Progress and results appear in a separate pop-up, or in an app dialog if the pop-up is blocked. Close is hidden while work is running. When finished, the view shows success (成功) or error (エラー), the result, and a Close button.

  • Show progress (経過を表示) at the top reopens the result of the job started in this management page.
  • Closing the management page or progress window does not cancel work already running on the server.
  • On error, read the affected rows, cause and completed counts before taking action. Some changes may already have been committed.
  • If deletion succeeded but recreation failed, that event may be temporarily missing. After checking the result, publishing the same targets and range again can recreate missing events.
  • After verification expiry or a lost connection, avoid repeatedly clicking Save or Publish. Verify again and use Show progress to check the job result.

Keep column positions and headers unchanged. Web deletion leaves row numbers in place. Deleting or reordering spreadsheet rows can change their Calendar mapping; use the Web panel to delete events.

10所有者の初回設定First-time setup for the owner

この区画は元シート所有者向けです。通常のスタッフは、配布された管理用Web URLからログインします。

This section is for the source spreadsheet owner. Regular staff use the management Web URL supplied to them.

初回設定の手順を開くExpand setup instructions
  1. 既存のGASへMain・SheetSetupを反映し、マニフェストは既存設定と比較して差分を適用します。Calendar v3・Sheets v4・Drive v3と必要なスコープを保持します。認証更新だけでシートを再初期化しません。
  2. エディターからcheckCalendarGoogleLoginGroupを実行し、所有者が追加承認を行います。共有・所属の診断が成功したことをログで確認します。
  3. 既存のWebデプロイを更新します。「次のユーザーとして実行」は元シート所有者、「アクセスできるユーザー」はGoogleアカウントを持つ全員です。管理機能の利用許可は指定グループで判定します。
  4. openCalendarLoginSetupを実行し、ログの「Googleログイン初回設定URL」を所有者のアカウントで開きます。シート内ダイアログは開きません。
  5. 設定フォームの「Googleに登録する戻り先URL」をコピーします。末尾は?ssjLogin=googleです。フォームを開く?ssjSetup=googleのURLは登録しません。
  6. 既存の共通Cloud（運用上の表示名：SSJ-Auth）のGoogle Auth Platformで、カレンダー用の「ウェブ アプリケーション」クライアントを用意します。「承認済みのリダイレクトURI」にコピーした値を登録します。GAS側のGCP「デフォルト」を切り替える操作は不要です。
  7. クライアント作成画面を閉じる前に設定JSONをダウンロードし、カレンダーの設定フォームで選択して「設定を保存」します。JSONやシークレットはGitやチャットへ置きません。設定保存後はGoogleで再確認します。

初回設定は所有者だけが利用できます。利用者の本人メールが空のとき、実行者のメールを代わりに使って設定を許可しません。カレンダーへの実際の編集権限は実行する所有者に必要です。

AIを使う場合は、既存Script Propertyの名前「Gemini API Key」に対応する値を所有者が管理します。Googleログイン用OAuthクライアントとは別の設定です。

  1. Update Main and SheetSetup in the existing GAS project. Compare and merge manifest changes while preserving Calendar v3, Sheets v4, Drive v3 and required scopes. An authentication update does not require reinitializing the spreadsheet.
  2. Run checkCalendarGoogleLoginGroup from the editor. The owner completes any additional Google consent and checks the sharing/membership diagnostic result.
  3. Update the existing Web deployment. Run it as the source spreadsheet owner and allow Google-account users. The app separately restricts management by designated-group authorization.
  4. Run openCalendarLoginSetup, then open the setup Web URL printed in its log using the owner account. This function does not open a spreadsheet dialog.
  5. Copy Google redirect URL (Googleに登録する戻り先URL) from the setup form. It ends in ?ssjLogin=google. Do not register the form-opening URL ending in ?ssjSetup=google.
  6. In the existing shared Cloud project (operational display name: SSJ-Auth), use Google Auth Platform to create a calendar-specific Web application client. Add the copied value under Authorized redirect URIs. The GAS project's default GCP association does not need changing.
  7. Before closing the client-creation screen, download its configuration JSON. Select it in the calendar setup form and save. Keep the JSON and secret out of Git and chat. Verify with Google again after saving.

Setup is restricted to the source owner. A blank active-user email is not replaced with the executing owner's email to grant access. Actual Calendar editing rights belong to the owner executing the app.

For AI, the owner manages the existing Script Property named Gemini API Key. It is separate from the OAuth client used for Google sign-in.
